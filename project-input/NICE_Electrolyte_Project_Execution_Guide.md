# NICE-Only Electrolyte Decision-Support Project

Version: 1.1
Evidence checked: 2026-08-09

## 1. Project objective

Build an AI-assisted clinical decision-support prototype for adult electrolyte abnormalities.

The system must:

1. Use NICE guidance as the only source of management recommendations.
2. Use a deterministic rule engine for every clinical output.
3. Use an LLM only for note extraction, missing-field questions, explanations and summaries.
4. Clearly state when NICE does not provide a complete pathway for the selected condition.
5. Keep journal articles separate as additional learning resources.

## 2. Recommended MVP scope

Start with the conditions that have the strongest NICE coverage:

- Hyperkalaemia in CKD, heart failure, AKI and IV-fluid contexts.
- IV-fluid-related hyponatraemia, hypernatraemia and hypokalaemia.
- Hypercalcaemia in suspected or confirmed primary hyperparathyroidism.

Keep these conditions visible but unsupported for definitive NICE-only management:

- General adult hypocalcaemia.
- General adult hypomagnesaemia.
- General adult hypermagnesaemia.
- General hyponatraemia, hypernatraemia, hypokalaemia and hypercalcaemia outside the NICE contexts in the rule catalogue.

## 3. Architecture

```text
Clinical note or structured form
        ↓
Local LLM extracts structured fields
        ↓
Schema validation and user confirmation
        ↓
Deterministic NICE rule engine
        ↓
Locked result: priority, action, limitation and source
        ↓
RAG explanation from approved NICE pages
        ↓
Additional PubMed/Europe PMC learning resources
```

## 4. Free technology stack

- Frontend: Next.js, TypeScript, Tailwind CSS and shadcn/ui
- Validation: Zod
- Database: Supabase PostgreSQL free tier or local PostgreSQL
- Rule engine: TypeScript
- Local LLM: Ollama with a small Qwen model
- Embeddings: embeddinggemma through Ollama
- Article search: Europe PMC and PubMed APIs
- Tests: Vitest, Playwright and GitHub Actions
- Demo deployment: Vercel, using synthetic data only

## 5. Project phases

### Phase 0 — Governance and scope

Tasks:
- Confirm adult-only scope.
- Decide whether pregnancy is excluded from the MVP.
- Nominate a clinical reviewer.
- Approve the NICE-only source policy.
- Define prohibited outputs, including medication doses generated by AI.

Deliverable:
- Signed scope and safety checklist.

Acceptance criteria:
- Every active clinical rule has a NICE source and recommendation section.
- Unsupported cases produce no treatment instruction.

### Phase 1 — NICE evidence inventory

Tasks:
- Store NICE guidance title, code, publication date, URL and relevant sections.
- Paraphrase recommendations without changing their meaning.
- Record the condition and context in which each recommendation applies.
- Record exclusions and limitations.

Deliverable:
- Approved NICE source catalogue.

Acceptance criteria:
- No active management rule cites a non-NICE source.
- Outdated or replaced guidance is not used as active logic.

### Phase 2 — Rule-engine implementation

Tasks:
- Implement rules from `nice_electrolyte_management_rules.csv`.
- Evaluate eligibility and context before comparing thresholds.
- Run the unsupported-scenario rule when no NICE rule matches.
- Return the rule ID and NICE section with every result.

Deliverable:
- Tested deterministic rule-engine package.

Acceptance criteria:
- Boundary tests pass.
- The LLM cannot alter rule-engine outputs.
- Missing values and unsupported units block evaluation.

### Phase 3 — AI note extraction

Tasks:
- Convert free-text notes into validated JSON.
- Require confirmation before running the rules.
- Never infer missing values.
- Strip names, addresses and identifiers from external searches.

Deliverable:
- Local LLM extraction service.

Acceptance criteria:
- Numeric values and units are extracted accurately on the held-out test split.
- Unsupported or uncertain fields are returned as null or unknown.
- Every extracted field is editable before submission.

### Phase 4 — Results interface

Display sections in this order:

1. Alert or priority banner.
2. Information used.
3. NICE-derived result.
4. Why the rule matched.
5. Limitations and unsupported areas.
6. Exact NICE guidance and section.
7. Additional articles and learning resources.

Acceptance criteria:
- Article cards are visually separated from management guidance.
- The result page never labels journal articles as NICE management.
- Unsupported conditions show a clear specialist/local-protocol message.

### Phase 5 — Evidence and article resources

Tasks:
- Link the triggered NICE guidance first.
- Search Europe PMC or PubMed using controlled terms, not patient notes.
- Rank guidelines, systematic reviews, meta-analyses and clinical reviews first.
- Cache results for 7 days.
- Use the LLM only to summarise supplied abstracts.

Acceptance criteria:
- Additional articles cannot change the clinical recommendation.
- Each article displays title, publication type, year, PMID/DOI and access status.
- AI summaries contain no unsupported treatment advice.

### Phase 6 — Testing

Required tests:
- Unit tests for every rule.
- Boundary tests for every threshold.
- Context tests for dialysis, CKD stage, RAAS status and confirmed PHPT.
- Missing-field and wrong-unit tests.
- Prompt-injection tests.
- UI tests for emergency, unsupported and no-abnormality states.
- Clinical review of representative cases.

Release criteria:
- 100% of safety boundary tests pass.
- No unsupported condition generates treatment instructions.
- Every active output displays a NICE source.
- Clinical reviewer signs off the rules.

### Phase 7 — Deployment

For a public portfolio demo:
- Use synthetic data only.
- Do not store patient names.
- Do not send clinical notes to public AI APIs.
- Run Ollama locally or pre-generate non-clinical summaries.
- Display a prominent prototype disclaimer.

For real clinical use:
- Stop and complete medical-device, clinical-safety, information-governance and security assessments before deployment.

## 7. Definition of done

The MVP is complete when:

- Hyperkalaemia and the selected limited-context conditions work end to end.
- NICE rules are clinician-approved.
- The LLM only extracts and explains.
- Unsupported conditions are handled safely.
- Results include the exact NICE source and recommendation section.
- Additional articles are clearly marked as learning resources.
- All automated and clinical-review tests pass.
